    API & Event Reference

    All endpoints are served through the Nginx API gateway (http://localhost/api/*) and require contextual user identity headers for role authorization.

    Authentication & Context Headers

    Requests passed to the gateway must supply client context headers:

    Header Name Type Description Example
    X-User-Role String Active RBAC role key department_manager, finance_manager, compliance_officer, procurement_director
    X-User-Id String Unique user identifier usr_sarah_01
    X-User-Name String User display name Dr. Sarah

    1. Document Intelligence API (/api/documents)

    Ingest Document

    Uploads a document (PDF, PNG, JPG, TIFF) to MinIO and triggers OCR + extraction.

    • Method: POST
    • Path: /api/documents/ingest
    • Roles: department_manager, procurement_director
    • Request: multipart/form-data
      • file: Binary file upload
      • source: upload | email | api | shared_folder
    • Response 200 OK: 
      {
  "document_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "status": "extracted",
  "doc_type": "invoice",
  "vendor_id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "overall_confidence": 0.96,
  "extraction_engine": "llm",
  "fraud_flag": false,
  "fraud_score": 0.02
}

    List Documents

    • Method: GET
    • Path: /api/documents
    • Query Params: status (received, processing, extracted, needs_review, validated), limit, offset
    • Roles: All roles

    Get Document Details

    • Method: GET
    • Path: /api/documents/{id}
    • Roles: All roles

    Review Extracted Fields

    • Method: POST
    • Path: /api/documents/{id}/review
    • Roles: department_manager, compliance_officer, procurement_director
    • Request Body: 
      {
  "corrected_fields": {
    "total_amount": 125000.0,
    "invoice_number": "INV-2026-901"
  },
  "approved": true
}

    2. Vendor Intelligence API (/api/vendors)

    List Vendors

    • Method: GET
    • Path: /api/vendors
    • Roles: All roles

    Onboard Vendor

    • Method: POST
    • Path: /api/vendors
    • Roles: compliance_officer, procurement_director
    • Request Body: 
      {
  "legal_name": "Bharat Pharma Supplies",
  "vendor_type": "pharma_distributor",
  "gst_number": "27AAACB2212P1ZA",
  "drug_license_number": "DL-MH-2025-1029",
  "drug_license_expiry": "2027-06-30",
  "fda_cdsco_registration_id": "CDSCO-DIST-2025-01",
  "contact_email": "supply@bharatpharma.in",
  "contact_phone": "+91-91234-56789"
}

    Resolve Vendor by Name

    Fuzzy matches an OCR extracted supplier string to canonical registered vendor. - Method: GET - Path: /api/vendors/resolve?name=Bharat+Pharma - Roles: All roles

    3. Approval Workflow API (/api/approvals)

    Submit Procurement Request

    • Method: POST
    • Path: /api/approvals/requests
    • Roles: department_manager, procurement_director
    • Request Body: 
      {
  "requested_by": "Dr. Sarah",
  "department": "Cardiology",
  "category": "consumables",
  "vendor_id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "items": [
    {"sku": "STENT-01", "quantity": 10, "unit_price": 12000.0}
  ],
  "total_value": 120000.0,
  "currency": "INR",
  "source_document_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6"
}

    Pending Approval Inbox

    Fetches approval requests awaiting decision by the caller's role. - Method: GET - Path: /api/approvals/inbox - Roles: All roles

    Decide on Request Step

    • Method: POST
    • Path: /api/approvals/requests/{id}/decide
    • Roles: Must match pending step role
    • Request Body: 
      {
  "decision": "approved",
  "decision_note": "Verified against quarterly budget allocations."
}

    4. Inventory Intelligence API (/api/inventory)

    Check Stock Availability

    • Method: GET
    • Path: /api/inventory/items
    • Roles: All roles

    Reserve Stock

    • Method: POST
    • Path: /api/inventory/reserve
    • Roles: department_manager, procurement_director
    • Request Body: 
      {
  "request_id": "a98c7654-2101-44af-9988-123456789abc",
  "sku": "DRUG-CEFTRIAXONE-1G",
  "quantity": 200
}

    5. Contract Intelligence API (/api/contracts)

    Generate Contract

    • Method: POST
    • Path: /api/contracts/generate
    • Roles: procurement_director
    • Request Body: 
      {
  "template_type": "supply_agreement",
  "vendor_id": "d290f1ee-6c54-4b01-90e6-d701748f0851",
  "request_id": "a98c7654-2101-44af-9988-123456789abc",
  "effective_date": "2026-11-01",
  "expiry_date": "2027-10-31"
}

    Dispatch for E-Signature

    • Method: POST
    • Path: /api/contracts/{id}/send-for-signature
    • Roles: procurement_director

    6. Risk Intelligence API (/api/risk)

    Get Vendor Risk Assessment

    • Method: GET
    • Path: /api/risk/vendors/{vendor_id}
    • Roles: All roles

    List Anomaly Flags

    Surfaces vendors flagged by IsolationForest or behavioral outlier rules. - Method: GET - Path: /api/risk/anomalies - Roles: All roles

    7. Kafka Event Topics Schema

    All events follow the envelope structure: 

    {
  "event": "topic_name",
  "data": { ... },
  "occurred_at": "2026-10-29T16:00:00Z"
}

    Event Topic Partition Key Schema Payload Highlights
    documents.processed document_id document_id, vendor_id, doc_type, status, confidence, fraud_flag, fraud_score, extracted_fields
    vendor.onboarded vendor_id vendor_id, legal_name, status, drug_license_number
    procurement.request.created request_id request_id, vendor_id, department, total_value, items
    approval.approved request_id request_id, vendor_id, approved_by_chain
    inventory.reserved request_id request_id, sku, batch_no, quantity, expires_at
    contract.signed contract_id contract_id, vendor_id, envelope_id, signed_at
    risk.assessed vendor_id vendor_id, risk_band, dimensions, anomaly_flag, is_cold_start
