    User Guide & Workflows

    This guide covers real-world usage scenarios in MediSource AI, illustrating how hospital procurement officers, department managers, and compliance leads interact with the system.

    1. Vendor Onboarding & Qualification

    Hospitals must rigorously verify pharmaceutical distributors and biomedical contractors prior to purchasing.

    Onboard a New Vendor via API

    curl -X POST http://localhost/api/vendors \
  -H "Content-Type: application/json" \
  -H "X-User-Role: procurement_director" \
  -d '{
    "legal_name": "Apex Medical Devices Pvt Ltd",
    "vendor_type": "equipment_supplier",
    "gst_number": "27AABCU9603R1ZX",
    "drug_license_number": "DL-MH-2024-88910",
    "drug_license_expiry": "2027-12-31",
    "fda_cdsco_registration_id": "CDSCO-MD-2024-0012",
    "contact_email": "orders@apexmed.com",
    "contact_phone": "+91-98200-11223"
  }'

    Automatic Validation Checks:

    1. GSTIN Checksum: Regex & state code validation against Indian GST format.
    2. Drug License Expiry: Prevents onboarding vendors whose pharmaceutical or medical distribution licenses have lapsed.
    3. Watchlist Screening: Automatic matching against regulatory and sanctions databases.

    2. Ingesting Invoices & Document Intelligence

    When a medical invoice or PO is received, it is ingested through the single-entry endpoint.

    Ingesting an Invoice

    curl -X POST http://localhost/api/documents/ingest \
  -H "X-User-Role: department_manager" \
  -F "file=@sample_invoice.pdf" \
  -F "source=upload"

    Ingestion Response:

    {
  "document_id": "7f8b9912-349c-48be-8123-5e9213456789",
  "status": "extracted",
  "doc_type": "invoice",
  "vendor_id": "c19b2234-9210-44af-8899-712399123456",
  "overall_confidence": 0.94,
  "extraction_engine": "llm",
  "fraud_flag": false,
  "fraud_score": 0.05,
  "extracted_fields": {
    "invoice_number": "INV-2026-901",
    "invoice_date": "2026-10-15",
    "total_amount": 125000.0,
    "tax_amount": 15000.0,
    "line_items": [
      {
        "sku": "MED-STENT-01",
        "description": "Drug-Eluting Coronary Stent",
        "batch_number": "BT-2026-A1",
        "expiry_date": "2028-06-30",
        "quantity": 10,
        "unit_price": 11000.0
      }
    ]
  }
}

    Review Queue Handling

    If confidence drops below 0.75 (e.g. low-resolution scanned fax) or fraud checks fail: - Status is set to needs_review. - Document appears in the review queue: GET /api/documents?status=needs_review. - A human operator corrects or verifies fields via POST /api/documents/{id}/review. - Approving re-emits a documents.reviewed Kafka event to proceed down the pipeline.

    3. Creating & Routing Procurement Approvals

    Once extracted, procurement requests are evaluated by Open Policy Agent (OPA).

    Initiating a Request

    curl -X POST http://localhost/api/approvals/requests \
  -H "Content-Type: application/json" \
  -H "X-User-Role: department_manager" \
  -d '{
    "requested_by": "Dr. Sarah",
    "department": "Cardiology",
    "category": "consumables",
    "vendor_id": "c19b2234-9210-44af-8899-712399123456",
    "items": [
      {"sku": "MED-STENT-01", "quantity": 10, "unit_price": 11000.0}
    ],
    "total_value": 110000.0,
    "currency": "INR"
  }'

    Dynamic Step Chain Generated:

    Because total value exceeds ₹100,000, OPA configures a multi-tier chain: 1. Department Manager (Dr. Sarah) — Approval SLA: 24h 2. Finance Manager (Mark) — Spend and budget validation 3. Procurement Director (Arthur) — High-value contract execution sign-off

    Making an Approval Decision:

    curl -X POST http://localhost/api/approvals/requests/{request_id}/decide \
  -H "Content-Type: application/json" \
  -H "X-User-Role: finance_manager" \
  -d '{
    "decision": "approved",
    "decision_note": "Budget verified against Q4 Cardiology allocations."
  }'

    4. Inventory Reservation & Cold-Chain Guardrails

    When a request is submitted, inventory_intelligence verifies stock and reserves units:

    curl -X POST http://localhost/api/inventory/reserve \
  -H "Content-Type: application/json" \
  -H "X-User-Role: department_manager" \
  -d '{
    "request_id": "a98c7654-2101-44af-9988-123456789abc",
    "sku": "MED-VAX-02",
    "quantity": 50
  }'

    Cold-Chain Integrity Protection

    If the requested SKU is marked cold_chain: true, the system: 1. Verifies that all units belong to a valid unexpired batch stored within temperature tolerances. 2. Enforces non-split reservations across incompatible batches. 3. If warehouse stock is insufficient, it immediately raises a backorder via inventory.backorder.

    5. Contract Generation & Digital E-Signature

    Upon final approval, contract_intelligence compiles an official agreement:

    curl -X POST http://localhost/api/contracts/generate \
  -H "Content-Type: application/json" \
  -H "X-User-Role: procurement_director" \
  -d '{
    "template_type": "supply_agreement",
    "vendor_id": "c19b2234-9210-44af-8899-712399123456",
    "request_id": "a98c7654-2101-44af-9988-123456789abc",
    "effective_date": "2026-11-01",
    "expiry_date": "2027-10-31"
  }'

    Dispatching E-Signature:

    curl -X POST http://localhost/api/contracts/{contract_id}/send-for-signature \
  -H "X-User-Role: procurement_director"
    The PDF is dispatched to OpenSign. When signed, the webhook updates status to signed and notifies the hospital legal archive.

    6. Real-Time Vendor Risk & Anomaly Monitoring

    Query real-time vendor risk profile and AI anomaly detection reasons:

    curl -X GET http://localhost/api/risk/vendors/c19b2234-9210-44af-8899-712399123456 \
  -H "X-User-Role: finance_manager"

    Risk Response:

    {
  "vendor_id": "c19b2234-9210-44af-8899-712399123456",
  "risk_band": "low",
  "overall_risk": 0.18,
  "dimensions": {
    "compliance_risk": 0.05,
    "fraud_risk": 0.02,
    "financial_risk": 0.22,
    "supplier_risk": 0.15,
    "spend_risk": 0.12,
    "operational_risk": 0.10
  },
  "anomaly_flag": false,
  "observation_count": 42,
  "is_cold_start": false
}
    If anomaly_flag is true, details are returned under anomaly_reasons (e.g. ["sudden_spend_spike_3x", "delivery_delays_detected"]).
